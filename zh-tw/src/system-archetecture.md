# 系統架構

Botnana Control 是專為工業自動化與半導體/精密設備設計的即時運動控制平台。系統將網頁操作介面 (Web HMI)、即時運動控制核心以及 EtherCAT 現場總線通訊進行清晰的分層設計，確保高可靠度、高即時性與維護便利性。

## 系統架構概觀


## 通訊連接埠與介面

控制器對外提供兩個獨立的網路通訊埠：

1. **HTTP 連接埠 `3000` (Web HMI 與軟體管理)**
   - 供工程師與操作人員透過瀏覽器（如 Google Chrome）直接連線，進行設備試車、監控、I/O 測試、設定檔備份/還原與軟體升級。
   - 不需額外安裝專用軟體，跨平台支援各類上位裝置。

2. **WebSocket 連接埠 `3012` (即時運動控制 API)**
   - 供客戶端自動化主控程式（如 C#、Python、JavaScript、C++）直連。
   - 採用標準 JSON-RPC 與即時腳本求值，提供極低延遲（啟用 `TCP_NODELAY`，通訊延遲約 0.14 ms）的即時運動指令派送與狀態回讀。
   - 支援官方釋出的 `botnana-apis` 客戶端函式庫。

## 控制器生命週期與運作狀態

Botnana Control 嚴格區分控制器的運作狀態，防止在硬體未就緒時執行運動指令：

| 控制器狀態 | 說明與特徵 |
|---|---|
| **Ready (就緒)** | EtherCAT 總線已成功配置，所有實體從站皆進入穩定操作模式 (**OP**)，週期資料交換正常。此時允許執行軸運動與即時控制。 |
| **Starting (啟動中)** | 控制器正在進行 EtherCAT 拓撲掃描、從站身分核對、Mailbox 參數配置及狀態轉換。畫面會顯示啟動進度與重試時間。 |
| **Unavailable / Fault (無法使用 / 故障)** | 控制器未啟動或啟動逾時。系統具備**可歸因的開機診斷**能力，當開機逾時時會明確指出未進入 OP 的具體從站位置（例如 `slaves not in OP: Slave 8 (PREOP)`），大幅縮短現場排錯時間。 |

即使控制器處於 Unavailable 狀態，Web HMI 與設定管理功能仍可正常使用，操作人員可檢視目前硬體偵測狀態、檢查設定檔或重新掃描總線。

## 設定檔持久化與安全防護

機台的所有核心設定均儲存於 `/etc/botnana-control/motion.toml`（TOML 格式），包括：
- 運動控制週期 (`period_us`)、軸數與軸組容量。
- EtherCAT 從站列表、產品身分、軸通道與 I/O 映射。
- 軸參數（速度、加速度、原點復歸模式、電子齒輪比/脈衝當量）。
- 軸組協調參數（幾何類型、同動軸映射、加加速度限制）。

### 安全管理原則：
1. **升級保護機制**：Debian 套件升級時，系統 100% 保留現有 `/etc/botnana-control/motion.toml`，絕不覆蓋客戶已試車完成的參數。
2. **HMI 設定安全流程**：HMI 上的編輯需經過審查 (Review) 與確認儲存 (Save)，儲存後的設定會在下一次受控啟動時正式套用，避免運作中參數突變造成機械危險。
3. **災難復原與配置傳輸**：操作介面提供一鍵下載設定備份，並支援在斷線或更換硬體時上傳復原設定檔。

## EtherCAT 總線整合優勢

1. **多品牌伺服與步進驅動器支援**：支援標準 CiA 402 設定檔與原廠專用模式（如東方馬達 AZ 系列原點模式 24）。
2. **即時總線熱恢復 (DC Recovery)**：具備 EtherCAT 分布式時鐘 (DC) 自動參考時鐘恢復能力，當總線發生短暫斷線或重連時，自動重新同步鎖定時鐘，防止軸控異常中斷。
3. **實體從站 AL State 即時可見度**：HMI 偵測列表中即時呈現各從站的應用層通訊狀態（OP、SAFEOP、PREOP、INIT），一目了然掌握總線健康度。
