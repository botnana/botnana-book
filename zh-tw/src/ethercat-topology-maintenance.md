# EtherCAT 拓撲維護

當獲授權的試車技術人員要刻意新增、移除、更換或重新排序 EtherCAT 從站時，請使用
拓撲維護。如果硬體配置不應改變，請使用一般 **Rescan EtherCAT**。如果故障不是由
核准的配置變更造成，請使用 [EtherCAT 控制器復原](ethercat-controller-recovery.md)。

掃描已連接硬體不會儲存或採用硬體。只有明確使用完整掃描建立提案、檢查影響、
儲存、套用該確切已儲存版本，而且控制器到達 **Ready** 後，變更的配置才會生效。

> **安全注意事項：**請遵守現場的上鎖、動作停用、電氣隔離及驗證程序。HMI 確認
> 只記錄您對機台已安全的聲明，不是安全連鎖。控制器無法使用、正在啟動或回報故障
> 時，請讓機台保持在核准的安全狀態。

## 瞭解拓撲狀態

**Controller & Topology** 會分開管理實體觀察結果、提議的編輯、已儲存設定及運作中
的控制器：

| HMI 狀態 | 意義 |
|---|---|
| **Configured slaves** | 維護期間用作已儲存比較基準的唯讀拓撲。 |
| **Detected slaves** | 最新一次成功維護掃描所得的唯讀硬體。一般啟動或重新掃描期間，則會跟隨每次最新完成的實體啟動掃描。 |
| **Proposed topology** | 明確選擇 **Use complete detected topology** 後產生的完整偵測拓撲。此處只能編輯 **Expected Alias**。 |
| **Shared draft** 及 **Draft version** | 正在檢查的設定，尚未儲存供啟動使用。 |
| **Saved profile** 及 **Saved version** | 持久儲存在控制器上的設定。 |
| **Running controller** | 目前控制機台的設定；只有儲存不會改變它。 |
| **Pre-maintenance controller settings** | 未套用提案而離開時，用來啟動控制器的確切保留設定。 |

各頁籤的數量可用來交叉檢查。Configured 與 Detected 數量不同本身不會造成任何
變更。維護期間，**Detected slaves** 只顯示該次成功維護掃描，不會和啟動掃描的
觀察結果混合。

請在 **Slave Configuration** 檢查驅動器、I/O、通道及其他從站類型設定。切換
**Controller & Topology** 頁籤不會取代該編輯器。

## 準備變更

進入維護前：

1. 記錄核准的實體變更、目前從站順序、別名、vendor ID、product code 及回復計畫。
   必要時拍攝標籤及配線。
2. 確認新控制器無法啟動時，可以恢復原硬體及配線。
3. 在 **Controller & Topology** 比較 **Configured slaves** 和 **Detected slaves**。
4. 完成現有設定編輯。儲存預定變更或捨棄不需要的變更，讓設定保持乾淨。
5. 停止正在使用控制器的指令稿、配方、HMI 工作及其他作業。
6. 讓機台進入現場核准的安全狀態。
7. 只有在可使用 **Enter topology maintenance**，且附近沒有顯示未解決原因時才繼續。

控制器可以是 **Ready**；如果刻意改變的實體配置已經和乾淨的已儲存設定不同，
控制器也可能是 **Failed**。

## 進入拓撲維護

1. 選擇 **Enter topology maintenance**。
2. 閱讀確認內容；只有在機台已安全時才確認。
3. 等待 Botnana Control 釋放控制器世代及 EtherCAT master。不要重複送出要求。
4. 確認可以使用 **Scan connected slaves**。
5. 確認 **Configured slaves** 和 **Detected slaves** 仍彼此分開，而且尚未產生提案。

此時控制器無法使用是正常狀態。進入維護不會改變草稿版本或已儲存版本。一般設定
編輯器仍可看見，但會在維護期間停用。

如果進入要求遭拒，請讀取畫面原因，不要繞過限制。原因可能是控制器工作尚未完成、
正在轉換狀態、有未儲存設定、已有另一項維護作業，或執行期資源無法安全釋放。

## 變更、掃描及比較硬體

1. 讓機台保持安全，並依現場及硬體說明隔離裝置電源。
2. 只執行已核准的新增、移除、更換或重新排序。
3. 檢查裝置電源、EtherCAT-IN/EtherCAT-OUT 方向、纜線接合及實體順序。只有在程序
   允許時才能恢復電源。
4. 選擇 **Scan connected slaves** 並等待完成。重新整理或關閉瀏覽器不會取消掃描。
5. 選擇 **Detected slaves**，確認來源指出目前的維護掃描。
6. 將每個位置、vendor ID、product code 及預期裝置和核准變更及實體標籤比較。

不能只選擇一部分。每個偵測到的資料列都必須屬於預定配置。若出現任何非預期資料
列，請修正硬體後再次掃描。新掃描會取代比較結果並使先前的檢查確認失效，但絕不會
暗中儲存硬體。

如果偵測拓撲和已儲存拓撲相同，可以離開並恢復維護前控制器設定。如果只需要改變
預期別名，仍可建立提案。

## 建立並檢查完整提案

1. 再次確認每個偵測資料列都是預定項目。
2. 選擇 **Use complete detected topology**。不能只採用部分拓撲。
3. 確認 **Proposed topology** 的位置、vendor ID 及 product code 和 **Detected
   slaves** 相同。
4. 必要時編輯 **Expected Alias**，只能輸入 0 至 65535 的整數。這會改變設定中的
   預期值，並可能重新定位參照；不會寫入實體從站 EEPROM。
5. 選擇 **Review consequences**。
6. 檢查每一項清除、預設、移動、保留及別名影響。
7. 只有在每個結果都符合核准的設定及映射計畫時才確認。

常見影響如下：

| 變更 | 必須檢查的內容 |
|---|---|
| 新增從站 | 只會建立最小項目；Botnana Control 不會猜測裝置設定或映射。 |
| 移除從站 | 檢查所有參照該從站的驅動器、軸、群組、I/O 或通道關係。 |
| 唯一裝置移動 | 依身分綁定的參照可能跟著移動，但仍須檢查和位置有關的假設。 |
| 不同型號更換 | 裝置專用設定會清除，不會複製到不同硬體。 |
| 無法區分的相同裝置 | Botnana Control 不會猜測移動關係；無法配對的設定會保守地清除。 |

不要只為了讓儲存按鈕可用而接受清除或預設值。如果影響不是預定結果，請取消、
修正硬體或計畫後重新掃描，或離開並捨棄草稿。

移除最後一個從站可以產生零資料列的有效提案。空的已儲存從站清單會被視為尚未
試車的拓撲；不代表系統會強制禁止日後連接任何從站。

## 儲存並套用新拓撲

1. 確認畫面所示草稿版本的所有必要影響都已接受。
2. 選擇 **Save reviewed topology (inactive)**。
3. 等待已儲存版本增加。確認控制器仍無法使用，而且 HMI 顯示已儲存拓撲尚未啟用。
4. 再次檢查已儲存版本及拓撲。
5. 選擇 **Apply saved topology**，確認訊息指出預定的已儲存變更。
6. 等待啟動。不要再送出套用或離開要求。
7. 只有在控制器顯示 **Ready** 後才能繼續。
8. 恢復動作許可前，確認從站順序、身分、必要裝置設定及機台狀態。

儲存不等於啟用。如果在儲存後停止，已儲存設定會和未啟用控制器不同，不可將機台
視為已就緒。

## 不採用掃描結果而離開

當偵測到的硬體不應在此時啟用時，請使用離開操作：

- 沒有未儲存拓撲草稿時，選擇 **Exit and restore pre-maintenance controller**。
- 檢查尚未完成時，選擇 **Exit and discard draft**；此時不能保留草稿。
- 草稿已完整檢查時，請明確選擇 **Exit and preserve draft** 或 **Exit and discard
  draft**。

離開會啟動保留的維護前控制器設定，不會採用偵測掃描。必要時先恢復相容的實體
硬體，再等待 **Ready** 並確認機台。

如果提案已經儲存，離開不會回復已儲存設定；已儲存拓撲會繼續保留但尚未啟用。

## 重新連線及故障處理

拓撲維護屬於控制器，不屬於單一瀏覽器。重新整理或重新連線後，請等待 **Restoring
topology maintenance state** 被目前階段取代。繼續前先確認階段、狀態修訂版、草稿及
已儲存版本、偵測快照、提案和檢查結果。如果另一個工作階段已先執行操作，請檢查
重新整理後的狀態，不要重複舊要求。

- **掃描失敗：**舊快照若標示為非目前狀態，不可使用。檢查電源、連線、纜線及偵測
  狀態；修正原因後才能重試。
- **儲存失敗：**草稿仍未儲存。修正回報的問題，並只在仍顯示相同草稿時重試。
- **套用或離開失敗：**讓機台保持安全，只使用 HMI 提供的重試或保留維護前設定
  離開操作。
- **顯示 Service recovery is required：**不要再啟動程序內操作。記錄階段、版本、
  世代及錯誤，請獲授權管理員依照 [EtherCAT 控制器復原](ethercat-controller-recovery.md#清理失敗時)
  中的 `bnc-motion` 程序處理。

向支援人員回報時，請記錄安裝的 Botnana Control 版本、核准變更、變更前後的實體
身分及順序、維護階段、草稿及已儲存版本、偵測快照、已接受的影響、最終控制器
狀態，以及任何中斷連線、重試或重新啟動服務的時間。
